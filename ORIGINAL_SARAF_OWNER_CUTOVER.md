## Single manual cutover entry point (on main, separate from the Draft PR)

GitHub → **Actions** → **Original Saraf Railway exit — manual gated
cutover** → **Run workflow**.

Enter the exact confirmation phrase **`PUBLISH_ORIGINAL_SARAF`** and
the exact 40-digit latest reviewed HEAD SHA of
`migration/telegram-native-serverless-poc` for `expected_sha`.

The action first executes the original synthetic regressions and Deno
type checks, then the *real original-bot signed user and admin*
read-only positive preflight. It will **REFUSE** cutover if ANY private
finance/KYC/admin/broadcast capability is disabled, wallets are missing,
the BotFather CLI access token targets another app, or the original bot
API token belongs to a different username. It creates a full original
React app and allowlisted Telegram handler package with no shadow SQLite
financial ledger, runs `tgcloud push`, checks the original webhook and
served Mini App. On a failed release it ATTEMPTS to restore the previous
Telegram Bot API webhook; if the Railway webhook used an unrecoverable
secret header, the old secret must be provided as the optional secret.

The workflow does **NOT** auto-authorize cash payout, automatically
fabricate remittance confirmation or delete Railway.
